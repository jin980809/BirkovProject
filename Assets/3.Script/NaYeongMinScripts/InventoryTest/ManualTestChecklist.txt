인벤토리 테스트 벤치 수동 검증 체크리스트
최종 갱신 2026-09-11 / 대상 씬 NaYeongMin

자동 테스트(EditMode 67개)가 잡지 못하는 것만 모았다.
드래그, 그리기, 입력, 저장 파일 같은 실제 상호작용이 대상이다.

[준비]
  1. NaYeongMin 씬을 연다. Hierarchy 에 InventoryTestBench 와 EventSystem 이 하나씩 있어야 한다.
  2. Play 를 누른다. 슬롯은 Play 시점에 생성된다.
  3. 화면 우측에 상태 메시지가 뜬다. 판정 사유가 여기 나오므로 항상 같이 본다.
  4. 아이콘이나 CSV 를 바꾼 뒤에는 Play 를 끄고
     Tools > NaYeongMin > 테스트 벤치 구성 을 다시 실행한다.

---------------------------------------------------------------
A. 초기 상태
---------------------------------------------------------------
A1  가방에 회복약 4 / 회복키트 1 / 물 1 / 밥 1 / 알람시계 1 / 지푸라기 1 이 있다.
A2  임시 기관권총, 임시 샷건, 임시 헬멧, 임시 방탄복이 가방에 있다.
A3  장비 슬롯 4칸이 전부 비어 있다.  <- 자동 착용 없음 확인
A4  장비 슬롯 라벨이 주 무기 / 보조 무기 / 머리 / 몸통 순이다.
A5  무기 퀵 2칸과 아이템 퀵 3칸이 비어 있다.
A6  창고 상태 표시가 닫힘이다.

---------------------------------------------------------------
B. 장비 착용 규칙
---------------------------------------------------------------
B1  기관권총을 보조 무기 칸에 드래그한다.
    -> 주 무기 칸에 들어간다. 보조 칸은 빈 채로 남는다.  (선입선출)
B2  샷건을 보조 무기 칸에 드래그한다.
    -> 보조 칸에 들어간다.
B3  가방의 다른 무기를 이미 찬 주 무기 칸에 드래그한다.
    -> 거부. 교환되지 않는다. 메시지에 사유가 뜬다.
B4  주 무기를 가방 빈 칸으로 드래그해 해제한 뒤 다른 무기를 넣는다.
    -> 성공. 바꿔 끼우려면 먼저 빼야 한다는 규칙 확인.
B5  헬멧을 무기 칸에 드래그한다.        -> 거부
B6  기관권총을 머리 칸에 드래그한다.     -> 거부
B7  회복약을 몸통 칸에 드래그한다.       -> 거부
B8  헬멧을 머리 칸, 방탄복을 몸통 칸에 드래그한다.  -> 각각 성공

---------------------------------------------------------------
C. 무기 퀵슬롯 링크
---------------------------------------------------------------
C1  장비 무기 칸에 무기를 넣는 즉시 무기 퀵 1 / 2 에 같은 아이템이 표시된다.
C2  장비에서 무기를 빼면 무기 퀵도 같이 빈다.
C3  무기 퀵슬롯을 드래그하려 하면 링크 안내 메시지가 뜨고 아무것도 옮겨지지 않는다.
C4  1 키와 2 키로 선택 무기가 바뀌고 해당 칸이 강조된다.
C5  무기 퀵슬롯을 클릭해도 같은 선택이 된다.

---------------------------------------------------------------
D. 아이템 퀵슬롯 매핑
---------------------------------------------------------------
D1  가방의 회복약을 아이템 퀵 1 에 드래그한다.
    -> 퀵에 표시되지만 가방에서 사라지지 않는다. 수량도 그대로다.
D2  같은 회복약을 아이템 퀵 3 에 다시 드래그한다.
    -> 퀵 1 이 비고 퀵 3 으로 옮겨간다.  (중복 지정 방지)
D3  무기를 아이템 퀵에 드래그한다.  -> 거부. 소모형과 특수만 가능.
D4  3 키를 눌러 회복약을 다 쓴다.
    -> 마지막 1개를 쓰는 순간 퀵슬롯이 비워진다.  (소멸 즉시 empty)
D5  퀵슬롯을 바깥으로 드래그하면 지정만 해제되고 아이템은 가방에 남는다.
D6  알람시계를 퀵에 지정하고 사용한다.
    -> 특수 효과 미구현 안내가 뜨고 수량이 줄지 않는다.

---------------------------------------------------------------
E. 창고 게이트
---------------------------------------------------------------
E1  창고가 닫힌 상태에서 가방 아이템을 창고로 드래그한다.  -> 거부
E2  창고 상호작용 버튼을 누른다. 창고 패널이 열리고 상태가 열림으로 바뀐다.
E3  보관과 회수가 정상 동작한다. 창고는 10 x 12 = 120칸이다.
E4  창고 슬롯을 클릭하면 가방으로 회수된다.
E5  버튼을 다시 눌러 닫으면 드래그가 다시 거부된다.

---------------------------------------------------------------
F. 전리품 상자와 RNG
---------------------------------------------------------------
F1  2x4 / 3x3 / 3x5 / 4x1 버튼을 눌러 칸 수가 8 / 9 / 15 / 4 로 바뀌는지 본다.
F2  같은 버튼을 여러 번 눌러 결과가 매번 달라지는지 본다.
F3  아무것도 안 나오는 빈 상자가 나와도 정상이다.
F4  전리품 슬롯을 클릭하거나 가리킨 뒤 E 키로 획득한다.
F5  전리품을 전부 비우면 풀 반환 안내 메시지가 뜬다.

---------------------------------------------------------------
G. 가방 포화
---------------------------------------------------------------
G1  가방 채우기 버튼을 누른다.
G2  전리품을 획득해 본다. -> 가방이 꽉 찼다는 메시지가 뜨고 획득되지 않는다.
G3  일반 아이템이 한 칸에 최대 5개까지만 쌓이는지 확인한다.
G4  무기와 특수 아이템은 한 칸에 1개만 들어간다.

---------------------------------------------------------------
H. 사망
---------------------------------------------------------------
H1  창고에 아이템을 몇 개 넣어 둔다.
H2  사망 버튼을 누른다.
H3  가방, 장비 4칸, 아이템 퀵슬롯이 모두 비었다.
H4  창고 내용물은 그대로 남아 있다.  <- 사망해도 창고 유지

---------------------------------------------------------------
I. 저장과 복구
---------------------------------------------------------------
I1  상태를 바꾼 뒤 저장 버튼을 누른다. 저장 경로가 메시지에 표시된다.
I2  초기화 버튼을 누른 뒤 불러오기를 누른다. -> 저장 시점 상태로 돌아온다.
I3  장비 슬롯과 아이템 퀵슬롯 매핑까지 복원되는지 확인한다.
I4  손상 복구 검사 버튼을 누른다. -> 백업에서 되살렸다는 메시지가 뜬다.
    이 검사는 별도 파일만 건드리며 실제 저장 파일은 손대지 않는다.
I5  저장 폴더: %USERPROFILE%/AppData/LocalLow/DefaultCompany/BirkovProject/NaYeongMinTestBench

---------------------------------------------------------------
J. 팀 머지 후 확인할 것
---------------------------------------------------------------
J1  Hierarchy 에 EventSystem 이 두 개 이상이면 클릭이 씹힌다. 하나만 남긴다.
J2  테스트 벤치의 useStandaloneKeyboard 가 true 면 1~5 키를 벤치가 직접 읽는다.
    팀 PlayerInputHandler 와 같이 돌릴 때는 false 로 두어 중복 처리를 막는다.
J3  테스트 UI 의 체력 허기 수분은 최대 30 임시값이다.
    팀 PlayerVitals 는 최대 100 이라 수치가 다르게 보이는 것이 정상이다.
    회복량 6 / 12 / 27 을 비율로 바꾸는 것은 합의 전까지 하지 않는다.
J4  UI 위에서 클릭할 때 사격이 같이 나가는지 확인한다. 나가면 별도 협의 대상이다.

---------------------------------------------------------------
K. 드롭 런타임 (LootRuntime.prefab)
---------------------------------------------------------------
K1  빈 씬이나 테스트 씬에 LootRuntime.prefab 을 올리고 Play 한다.
K2  콘솔에 초기화 실패 로그가 없으면 IsReady 가 true 다.
K3  Spawn 을 30회 넘게 호출하면 31회째부터 null 이 온다. 풀 고갈 처리 확인.
K4  전리품을 비운 오브제가 자동으로 비활성화되어 풀에 돌아가는지 본다.

---------------------------------------------------------------
결과 기록
---------------------------------------------------------------
실패한 항목은 번호와 화면 메시지를 그대로 적어 둘 것.
메시지가 판정 사유를 담고 있어 원인 추적이 빨라진다.
